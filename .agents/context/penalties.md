# Penalties correction and payroll context

Start in `Backend/penalties/services.py`, `payroll.py`, `views.py`, and `test_penalties.py`. The approved schedule remains the frozen catalog; do not invent new printed recurrence levels.

- Penalty contract years use `penalty_year_cycle`, anchored to contract start, then hire date, then `PENALTIES_EFFECTIVE_FROM`. Contract expiry does not extend an anniversary year. Leave's separate contract helper is unchanged.
- Waiving an earlier unapplied absence-wage band flags downstream same-spell issued allocations for manual review, holds mutable deductions, and stores released dates plus proposed reassessment dates. These proposals are not payable reservations; explicit reopen recomputes coverage against the current ledger. Waiving an applied earlier band retains paid coverage.
- Unworked absence wages use actual eligible missed-shift dates. `absence_dates` records measured evidence; `wage_absence_dates` records the uncovered dates charged on issuance. Prior applied charges continue to cover those dates even after waiver. Older rows without date-level wage evidence block another absence wage assessment in that spell for HR reconciliation.
- Same-kind changed attendance evidence preserves issued amounts and routes the record to `resolution.decision = manual_review`; mutable deductions are held. Disappeared evidence retains the existing automatic waiver behavior for unapplied rows and manual review for applied rows.
- `_manual_review` stores `previous_resolution` and `held_from` (the deduction status before the hold). An unapplied attendance review clears itself when evidence returns to exactly the issued snapshot; only a deduction held by the review returns to `pending_review`.
- HR can waive correction reviews through `/api/penalties/{id}/resolve/`. `decision=reopen` is available only for an unapplied automatic review; `services.current_replacement` recomputes the replacement from the current daily result or current absence spell (never the stored proposal) and 409s when none exists. Reopening is explicitly audited, refreshes the candidate note, sets `resolution.reopened_at`, voids its former mutable deduction, and re-checks downstream recurrence. `decision=rerate` (`services.rerate_recurrence`) clears unapplied recurrence-only reviews by re-rating occurrence/action/fine with the issue rules; extra wages are unchanged. Applied claims never reopen, re-rate, or change finalized payroll totals.
- Backdated issuance orders by date and primary key, then flags downstream issued/disputed/applied snapshots whose expected recurrence differs. Waived rows currently do not count; this preserves the prior conservative behavior pending HR policy confirmation.
- Lock order is payroll run (payroll operations only), sorted employee profiles, penalty records, deductions, payroll items/payslips. Attendance and penalty actions acquire the profile before penalty/deduction mutation. Payroll reads eligibility from freshly locked penalty rows.
- Approved Exit/During Shift adjustment intervals suppress departure/after-hours candidates only when their union covers the complete measured interval. Incomplete/nonoverlapping intervals remain reviewable.
- A lone typed checkout or lone opaque fallback punch cannot establish arrival: the attendance projection keeps its check-in (legacy late classification unchanged), `calculation_inputs.lone_opaque_punch` is set, and penalties skip late/early/after-hours candidates for that day. Late-policy and penalty rollout dates are independent; working-day/permission inputs persist before candidate reconciliation.
- Monetary issuance requires positive total salary. Pure warnings/nonmonetary actions remain available. Invalid rollout configuration is a Django system-check error (`penalties.E001`).
- Frozen catalog migrations preserve reference identities on rollback. Migration `0004` refreshes existing catalog policy values without changing issued monetary/action snapshots. Reversing the data operation intentionally retains catalog rows.

- Automatic late warnings (company policy, not the printed schedule): W01/W02/W07 occurrences 1-3 per month are written warnings; occurrence 4+ uses the printed levels shifted by two (`AUTO_WARNING_ROWS`, `EXTRA_AUTO_WARNINGS`, `_rated_level`). Off until `PENALTY_AUTO_WARNINGS_EFFECTIVE_FROM` is set; only incidents on/after it. Candidates start `automation=warning_pending`; hourly `penalties.tasks.issue_auto_warnings` issues settled ones (`PENALTY_AUTO_WARNING_SETTLE_HOURS` after shift end, default 12) per employee in date order under the profile lock (`skip_locked`), renders the level 1 late-notice PDF (`penalties/warning_notices.py`, blank occurrence/percentage) and delivers in-app + WhatsApp in the same transaction; three failures release the candidate to HR. Occurrence 4+ is released to the normal HR queue. W07 keeps its unworked-time wage. HR lists hide automatic records unless HR action is needed or `include_automated=true`; employees never receive counts (serializer nulls `occurrence_number`). Employees may acknowledge/dispute automatic warnings. Waiving an issued automatic warning sends one withdrawn notice. Download: `GET /api/penalties/{id}/warning-notice/`. Tests: `test_auto_warnings.py`, `test_concurrency.py`.

Operational signals use existing Python logging: `penalty_payroll_claims_reconciled`, `penalty_payroll_finalized`, `penalty_notification_failed`, `penalty_auto_warning_failed`, `penalty_auto_warnings_processed`, and bounded `penalty_hr_candidates_aged` (automatic `warning_pending` candidates excluded). Run `python manage.py check_aged_penalties` from the existing operational scheduler at least daily; it reports up to 100 candidates pending for at least seven days (measured from `resolution.reopened_at` when a candidate was reopened, else `created_at`) and sends no external provider requests. Scheduler registration, log alert routing, escalation ownership, and alert thresholds require operator confirmation before release. This command is not automatically scheduled by this change.

Focused regression coverage: `Backend/penalties/test_penalties.py`, `test_concurrency.py` (a `TransactionTestCase` with `serialized_rollback` that reloads serialized seed rows after its flush, so `--reuse-db` keeps the catalog), attendance calculation/policy/working-day tests, payroll attendance-deduction tests, permission attendance integration tests, and frontend penalty detail/API tests.

Remaining policy decisions: whether waived incidents count toward recurrence; contractual anniversary treatment of February 29 (currently February 28 in non-leap years); refund/recovery procedure for historical applied duplicate wages; and the printed absence schedule's missing continuous day-15 action. Applied payroll corrections need an explicit separate settlement/refund process; this feature records review without fabricating one.
